دليل أتمتة نشر تطبيقات Flutter على Google Play Store

دليل احترافي تفاعلي متكامل لإعداد خط سير عمل (CI/CD Pipeline) متطور باستخدام GitHub Actions لبناء وتوقيع ورفع حزم تطبيقات Flutter (Android App Bundle - .aab) تلقائياً إلى Google Play Store مع زيادة أرقام الإصدارات آلياً ودعم التشغيل اليدوي والدمج الآمن.

⚡
Ubuntu Runner
سيرفر مجاني وسريع جداً
🔄
Auto Versioning
توليد Build Number تلقائي
🔒
Zero-Credential
حساب خدمة رسمي مشفر
📦
.AAB Format
توليد وتوقيع حزم Release
⚡ المخصص التفاعلي لأوامر مشروعك (Live Code Customizer)

أدخل بيانات تطبيقك ومفاتيح التوقيع في الحقول أدناه، وسيتم تحديث وتخصيص جميع أوامر الـ Terminal وأكواد الـ Gradle و YAML في كامل الصفحة تلقائياً لتناسب مشروعك مباشرة!

1

نظرة عامة ومخطط تدفق العمل (Architecture Workflow)

تعتمد آلية الرفع التلقائي لمتجر جوجل بلاي على بيئة عمل خالية تماماً من التدخل اليدوي، حيث يقوم GitHub Actions بالتعامل مع عملية البناء والتوقيع والرفع من خلال تدفق سحابي محكم:

1
Trigger Event
دمج التعديلات على فرع release أو التشغيل اليدوي بضغطة زر مع تحديد رقم إصدار اختياري.
2
Setup Environment
تجهيز Java 17 و Flutter SDK على سيرفر Ubuntu فائق السرعة مع تفعيل الـ Cache لـ Gradle.
3
Dynamic Versioning
استخراج الإصدار وحساب Build Number جديد تلقائياً (Base + GitHub Run Number) لمنع تكرار الإصدارات.
4
Restore Keystore
فك تشفير ملف الـ Keystore المشفر Base64 وحقن ملف key.properties لحظياً لتوقيع التطبيق.
5
Build Release AAB
أمر flutter build appbundle --release لإنتاج حزمة .aab مصغرة وموقعة رسمياً.
6
Upload via API
رفع الحزمة لمسار Internal Testing في Google Play Console عبر Service Account بدون إعلانات أو متصفح.
2

المتطلبات الأساسية للبدء

📋 قائمة المتطلبات الأساسية
  • حساب Google Play Developer Console: حساب نشط ومفعل مع دفع رسوم التسجيل (25$ لمرة واحدة).
  • مشروع مسجل في Google Cloud Platform: مربوط بنفس المنظمة أو البريد الإلكتروني.
  • اسم حزمة التطبيق (Package Name / Application ID): مثل: com.codebyte.mondera ويجب أن يكون متطابقاً في android/app/build.gradle.kts و AndroidManifest.xml و Google Play Console.
  • مستودع المشروع على GitHub: مع صلاحية تعديل الـ Settings وإضافة الـ Secrets.
⚠️
ملاحظة في غاية الأهمية (شرط جوجل الإلزامي):
لا تسمح Google Play API إطلاقاً برفع أول نسخة من التطبيق عبر الـ API. يجب رفع ملف .aab الأول يدوياً لمرة واحدة فقط عبر متصفح الويب في Google Play Console (داخل مسار Internal Testing مثلاً) لإتمام تهيئة مسار التوقيع وتأكيد الاسم وحجم التطبيق، وبعد ذلك ستعمل الأتمتة للأبد!
3

إنشاء حساب خدمة Google Cloud واستخراج مفتاح الـ JSON

حساب الخدمة (Service Account) هو هوية برمجية تسمح لـ GitHub Actions بالتواصل المباشر والآمن مع Google Play Console لرفع الحزم دون الحاجة إلى إدخال اسم مستخدم أو كلمة مرور أو رموز OTP:

  1. افتح لوحة تحكم Google Cloud Console، وتأكد من اختيار مشروع التطبيق المناسب في القائمة العلوية.
  2. تفعيل الـ API: انتقل إلى صفحة المكتبة وقم بتفعيل Google Play Android Developer API عبر الضغط على Enable:
    👉 Google Play Android Developer API Link
  3. انتقل لصفحة حسابات الخدمة عبر القائمة الجانبية:
    👉 IAM & Admin > Service Accounts
  4. اضغط على زر + Create Service Account:
    • Service account name: play-store-actions
    • Service account ID: سيتم توليده تلقائياً.
    • اضغط Create and continue.
    • في حقل الدور (Role): اختر Basic > Editor (أو Service Account User).
    • اضغط Done.
  5. ستلاحظ ظهور الحساب في الجدول، انسخ عنوان البريد الإلكتروني الخاص به (مثال: play-store-actions@<project-id>.iam.gserviceaccount.com) لأننا سنمنحه الصلاحيات في الخطوة القادمة.
  6. اضغط على النقاط الثلاث ⋮ (Actions) في أقصى اليمين لنفس الحساب > واختر Manage keys.
  7. اضغط Add Key > Create new key > اختر نوع المفتاح JSON واضغط Create.
💡
تم تحميل ملف الـ JSON بنجاح: سيتم تنزيل ملف بامتداد .json على جهازك. احتفظ به جيداً وبسرية تامة، لأن هذا الملف يحتوي على المفتاح الخاص للتواصل مع Google Play.
4

ربط حساب الخدمة وإعطاء الصلاحيات في Google Play Console

بعد إنشاء الحساب في Google Cloud، يجب ربطه داخل Google Play Console ومنحه إذن رفع الإصدارات للتطبيق المحدد:

  1. افتح لوحة تحكم Google Play Console.
  2. من القائمة الجانبية في الصفحة الرئيسية، اختر المستخدمون والأذونات (Users and permissions).
  3. اضغط على زر دعوة مستخدمين جدد (Invite new users).
  4. في خانة البريد الإلكتروني (Email Address): الصق إيميل حساب الخدمة الذي نسخته سابقاً:
    play-store-actions@<project-id>.iam.gserviceaccount.com
  5. في تبويب أذونات التطبيق (App permissions):
    • اضغط على إضافة تطبيق (Add app) وحدد تطبيقك (com.codebyte.mondera).
    • فعّل الصلاحيات التالية:
      • إنشاء وتعديل الإصدارات في المسارات الاختبارية (Create & edit releases to testing tracks)
      • طرح الإصدارات في المسارات الاختبارية (Release to testing tracks)
      • طرح الإصدارات في الإنتاج (Release to production) (اختياري إذا أردت الرفع المباشر للمتجر)
  6. اضغط على زر إرسال الدعوة (Invite user) في أسفل الصفحة.
ℹ️
ملاحظة التزامن: قد يستغرق سريان الصلاحيات في Google Play Console ما بين 5 إلى 15 دقيقة بعد الإضافة لتتعرف عليها واجهات الـ API.

ملف التوقيع Keystore (.jks) والتشفير إلى Base64

تتطلب تطبيقات أندرويد توقيع كل حزمة Release بمفتاح تشفيري خاص (Keystore). لضمان الأمان، لا نرفع ملف المفتاح أبداً إلى GitHub، بل نقوم بتحويله إلى نص مشفر (Base64) ونضعه كـ Secret.

نفذ الأمر التالي في مجلد المشروع لتحويل ملف الـ Keystore الحالي إلى نص مشفر Base64 في سطر واحد:

macOS / Linux Terminal 
base64 -i android/app/keystore.jks | tr -d '\r\n' > android_keystore_base64.txt
Windows PowerShell 
[Convert]::ToBase64String([IO.File]::ReadAllBytes("android/app/keystore.jks")) | Out-File -Encoding ASCII android_keystore_base64.txt

سيتم إنشاء ملف باسم android_keystore_base64.txt، افتحه وانسخ كل محتواه.

إذا كان هذا تطبيقاً جديداً بالكامل، يمكنك إنشاء ملف Keystore جديد رسمي ومخصص للتطبيق عبر أداة keytool:

Terminal (Keytool Command) 
keytool -genkey -v -keystore android/app/keystore.jks \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -alias upload \
  -storepass MyStrongStorePass123 \
  -keypass MyStrongKeyPass123

بعد إنشائه، قم بتشفيره كما في الخيار (أ) وانسخ الناتج.

🚨
تحذير أمني صارم:
لا تقم برفع ملف keystore.jks أو android_keystore_base64.txt إلى مستودع الـ Git أبداً! تأكد من إضافة *.jks و *_base64.txt إلى ملف .gitignore.
6

إضافة المفاتيح السرية في GitHub Secrets

انتقل إلى مستودع تطبيقك على GitHub وتوجه إلى:
Settings > Secrets and variables > Actions > واضغط على زر New repository secret:

اسم المفتاح السري (Secret Name) الوصف ومصدر القيمة المطلوبة
ANDROID_KEYSTORE_BASE64 المحتوى النصي الكامل لملف android_keystore_base64.txt الذي قمنا بتشفيره.
ANDROID_STORE_PASSWORD كلمة سر مخزن المفاتيح (القيمة الحالية المحددة: MyStrongStorePass123).
ANDROID_KEY_ALIAS اسم المفتاح داخل الـ Keystore (القيمة الحالية المحددة: upload).
ANDROID_KEY_PASSWORD كلمة سر المفتاح الخاص (القيمة الحالية المحددة: MyStrongKeyPass123).
PLAY_STORE_JSON_KEY محتوى ملف الـ .json الذي قمنا بتنزيله من Google Cloud Service Account بالكامل وبنفس تنسيقه.

تهيئة ملفات المشروع (build.gradle.kts & key.properties)

لكي يتعرف Gradle على مفاتيح التوقيع في السيرفر دون كتابة كلمات السر في الكود، نقوم بتهيئة android/app/build.gradle.kts (أو build.gradle) لقراءة الإعدادات من ملف key.properties:

1) ملف android/app/build.gradle.kts (صيغة Kotlin DSL الحديثة):
Kotlin (build.gradle.kts) 
import java.util.Properties
import java.io.FileInputStream

val keystoreProperties = Properties()
val keystorePropertiesFile = rootProject.file("key.properties")
if (keystorePropertiesFile.exists()) {
    keystoreProperties.load(FileInputStream(keystorePropertiesFile))
}

android {
    namespace = "com.codebyte.mondera"
    compileSdk = flutter.compileSdkVersion
    ndkVersion = flutter.ndkVersion

    defaultConfig {
        applicationId = "com.codebyte.mondera"
        minSdk = flutter.minSdkVersion
        targetSdk = flutter.targetSdkVersion
        versionCode = flutter.versionCode
        versionName = flutter.versionName
    }

    signingConfigs {
        if (keystorePropertiesFile.exists()) {
            create("release") {
                keyAlias = keystoreProperties.getProperty("keyAlias")
                keyPassword = keystoreProperties.getProperty("keyPassword")
                storeFile = file(keystoreProperties.getProperty("storeFile"))
                storePassword = keystoreProperties.getProperty("storePassword")
            }
        }
    }

    buildTypes {
        release {
            signingConfig = if (keystorePropertiesFile.exists()) {
                signingConfigs.getByName("release")
            } else {
                signingConfigs.getByName("debug")
            }
            isMinifyEnabled = false
            isShrinkResources = false
        }
    }
}
2) ملف android/.gitignore:

تأكد من وجود الأسطر التالية داخل android/.gitignore لمنع تسريب بيانات التوقيع المحلية:

.gitignore 
key.properties
*.jks
*.keystore
*_base64.txt

ملف سير العمل الكامل (.github/workflows/deploy_android.yml)

أنشئ الملف في المسار: .github/workflows/deploy_android.yml داخل مشروعك، والصق الكود التالي:

YAML (.github/workflows/deploy_android.yml) 
name: Deploy Android to Google Play Store

on:
  push:
    branches:
      - release
  pull_request:
    branches:
      - release
  workflow_dispatch:
    inputs:
      custom_build_number:
        description: 'رقم إصدار محدد يدوياً (اختياري - اتركه فارغاً للزيادة التلقائية)'
        required: false
        default: ''

jobs:
  deploy:
    name: Build & Upload to Google Play
    runs-on: ubuntu-latest
    timeout-minutes: 30

    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Set up Java 17
        uses: actions/setup-java@v4
        with:
          distribution: 'temurin'
          java-version: '17'
          cache: 'gradle'

      - name: Set up Flutter
        uses: subosito/flutter-action@v2
        with:
          channel: 'stable'
          cache: true

      - name: Calculate Version & Auto-Increment Build Number
        id: versioning
        run: |
          RAW_VERSION=$(grep '^version:' pubspec.yaml | sed -E 's/version:[[:space:]]*//')
          VERSION_NAME=$(echo "$RAW_VERSION" | cut -d'+' -f1)
          BASE_BUILD=$(echo "$RAW_VERSION" | cut -d'+' -f2)

          if [ -z "$BASE_BUILD" ] || [ "$BASE_BUILD" = "$VERSION_NAME" ]; then
            BASE_BUILD=100
          fi

          CUSTOM_BUILD="${{ inputs.custom_build_number }}"
          if [ -n "$CUSTOM_BUILD" ]; then
            BUILD_NUMBER="$CUSTOM_BUILD"
          else
            BUILD_NUMBER=$(( BASE_BUILD + GITHUB_RUN_NUMBER ))
          fi

          sed -i "s/^version:.*/version: $VERSION_NAME+$BUILD_NUMBER/g" pubspec.yaml

          echo "VERSION_NAME=$VERSION_NAME" >> $GITHUB_ENV
          echo "BUILD_NUMBER=$BUILD_NUMBER" >> $GITHUB_ENV
          echo "========================================="
          echo "🚀 Deploying Android Version: $VERSION_NAME (Build $BUILD_NUMBER)"
          echo "========================================="

      - name: Configure Keystore & Signing Credentials
        env:
          ANDROID_KEYSTORE_BASE64: ${{ secrets.ANDROID_KEYSTORE_BASE64 }}
          ANDROID_STORE_PASSWORD: ${{ secrets.ANDROID_STORE_PASSWORD }}
          ANDROID_KEY_ALIAS: ${{ secrets.ANDROID_KEY_ALIAS }}
          ANDROID_KEY_PASSWORD: ${{ secrets.ANDROID_KEY_PASSWORD }}
        run: |
          # فك تشفير ملف التوقيع Keystore
          python3 -c "import base64, os; s = os.environ['ANDROID_KEYSTORE_BASE64'].strip(); s += '=' * (-len(s) % 4); open('android/app/keystore.jks', 'wb').write(base64.b64decode(s))"

          # كتابة ملف key.properties لـ Gradle
          cat << EOF > android/key.properties
          storePassword=$ANDROID_STORE_PASSWORD
          keyPassword=$ANDROID_KEY_PASSWORD
          keyAlias=$ANDROID_KEY_ALIAS
          storeFile=keystore.jks
          EOF
          sed -i 's/^[[:space:]]*//' android/key.properties

      - name: Install Dependencies
        run: flutter pub get

      - name: Build Android App Bundle (AAB)
        run: |
          flutter build appbundle --release \
            --build-name="$VERSION_NAME" \
            --build-number="$BUILD_NUMBER"

      - name: Upload to Google Play (internal)
        uses: r0adkll/upload-google-play@v1
        with:
          serviceAccountJsonPlainText: ${{ secrets.PLAY_STORE_JSON_KEY }}
          packageName: com.codebyte.mondera
          releaseFiles: build/app/outputs/bundle/release/*.aab
          track: internal
          status: completed

استراتيجية فرع release والتشغيل والمتابعة

تم ضبط ملف الـ Workflow ليعمل عند دمج الكود في فرع release، مما يمنحك تحكماً كاملاً وحرية أثناء التطوير اليومي دون استهلاك موارد أو إرسال نسخ غير جاهزة إلى المتجر:

1) دورة النشر التلقائي عبر Git:
Git Release Flow 
# 1. التبديل إلى فرع release
git checkout release

# 2. دمج التعديلات من فرع التطوير
git merge main

# 3. دفع التعديلات لتشغيل الـ CI/CD فوراً
git push origin release
2) التشغيل اليدوي (Manual Dispatch):

يمكنك دائماً رفع التطبيق بضغطة زر من واجهة GitHub:
انتقل إلى تبويب Actions > اختر Deploy Android to Google Play Store من القائمة الجانبية > اضغط Run workflow > يمكنك إدخال custom_build_number محدد إذا رغبت، أو تركه فارغاً لتتولى الخوارزمية حسابه تلقائياً.

دليل استكشاف الأخطاء وحلولها (Troubleshooting & FAQ)

❌ Google Play Android Developer API has not been used in project before or it is disabled
السبب: واجهة الـ API غير مفعلة داخل مشروع Google Cloud.
الحل: ادخل على رابط الـ API في Cloud Console واضغط على Enable، ثم انتظر 5 دقائق وأعد تشغيل الـ Workflow.
❌ The caller does not have permission for the requested application
السبب: إيميل الـ Service Account لم تتم دعوته في Google Play Console، أو لم يتم منحه صلاحية تطبيقك المحدد.
الحل: اذهب لـ Play Console > المستخدمون والأذونات > تأكد من وجود إيميل حساب الخدمة وتحت تبويب "أذونات التطبيق" قم بإضافة تطبيقك وتفعيل صلاحية "Releases".
❌ Cannot upload initial release using the API. Please upload the first APK/AAB manually
السبب: سياسة Google Play تمنع رفع أول إصدار عبر الـ API للتطبيقات الجديدة.
الحل: قم ببناء التطبيق محلياً flutter build appbundle --release وارفعه يدوياً لمرة واحدة فقط عبر متصفح الويب في المسار التجريبي الداخلي (Internal Testing). بعد إتمام الرفع اليدوي الأول، ستعمل الـ Actions بنجاح تلقائياً.
❌ Version code XX has already been used for this package
السبب: رقم الـ Build Number / Version Code مستخدم مسبقاً في مسار بالمتجر.
الحل: قم بزيادة رقم الإصدار في pubspec.yaml (مثلاً 1.0.0+150) أو عند تشغيل الـ Workflow يدوياً اكتب رقماً أعلى في حقل custom_build_number.
❌ Keystore was tampered with, or password was incorrect
السبب: خطأ في كلمة سر الـ Store أو الـ Key أو تلف في نص الـ Base64 أثناء النسخ.
الحل: تأكد من عدم وجود مسافات فارغة أو أسطر مقطوعة في ANDROID_KEYSTORE_BASE64، وتأكد من مطابقة ANDROID_STORE_PASSWORD و ANDROID_KEY_PASSWORD للمفتاح الأصلي.
