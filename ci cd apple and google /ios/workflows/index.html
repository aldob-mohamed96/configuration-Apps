المتطلبات الأساسية قبل البدء
قبل الشروع في كتابة الأوامر، تأكد من توفر الآتي لدى فريقك:
  • حساب Apple Developer Program نشط (سواء كان حساب شركة أو فرد).
  • وجود تطبيق مسجل في App Store Connect > Apps يحمل نفس الـ Bundle ID.
  • مستودع المشروع مرفوع ومُدار على GitHub ولديك صلاحيات Admin لإضافة الـ Secrets.
  • جهاز Mac لتوليد شهادة التوزيع أول مرة فقط (أو استخدام أوامر OpenSSL الموضحة بالأسفل).
1
استخراج مفتاح App Store Connect API
لماذا نحتاج هذا المفتاح؟
يُتيح هذا المفتاح لسيرفرات GitHub Actions رفع الحزمة إلى App Store Connect مباشرة عبر أداة Apple الرسمية (xcrun altool) دون الحاجة لإدخال بريد وكلمة مرور أو طلب كود التحقق الثنائي (2FA).
🔗 انتقال مباشر إلى صفحة: App Store Connect > Users and Access > Integrations
  1. افتح الرابط أعلاه وسجل دخولك بحساب المطور.
  2. إذا كانت هذه أول مرة، اضغط زر Request Access ووافق على اتفاقية استخدام الـ API.
  3. تحت قسم Team Keys، اضغط على علامة الزائد `+` لإنشاء مفتاح جديد:
    • Name: اكتب اسماً واضحاً مثل GitHub Actions Deployer.
    • Access: اختر صلاحية App Manager أو Admin (لتتمكن الأداة من الرفع وإدارة الإصدارات).
  4. اضغط Generate.
  5. ستظهر البيانات التالية (احفظها في ملف نصي آمن):
    • Key ID: كود مكون من 10 خانات أبجدية ورقمية (مثال: U5943UX5VN).
    • Issuer ID: كود UUID يظهر أعلى الجدول (مثال: 7b528716-19b5-407f-98dc-9ae2e3fab928).
    • ملف المفتاح (.p8): اضغط على Download API Key لتحميل الملف.
⚠️
تنبيه هام جداً بخصوص ملف الـ .p8:
زر تحميل ملف الـ API Key يظهر لمرة واحدة فقط في بوابة أبل. إذا ضاع منك الملف فلن تتمكن من تحميله ثانية وستضطر لإنشاء مفتاح جديد (Revoke & Create New).
2
إنشاء شهادة التوزيع Apple Distribution (.p12)
توليد الشهادة والمفتاح الخاص بشكل آمن عبر الـ Terminal
لتفادي أي تعقيد أو مشاكل تصدير من برنامج Keychain Access، سنولد طلب توقيع الشهادة (CSR) والمفتاح الخاص، ثم ندمجها في ملف .p12 محمي بكلمة مرور:

أ) توليد ملف طلب الشهادة (CSR) والمفتاح الخاص:

افتح الـ Terminal في أي مجلد فارغ ونفذ الأمر التالي:

Terminal (Bash)
# 1. إنشاء المفتاح الخاص وملف طلب الشهادة CSR openssl req -nodes -newkey rsa:2048 \ -keyout distribution_private_key.key \ -out CertificateSigningRequest.certSigningRequest \ -subj "/emailAddress=developer@yourcompany.com/CN=Apple Distribution/C=US"

ب) رفع ملف الـ CSR وتحميل شهادة Apple:

🔗 بوابة Apple Developer: قائمة الشهادات (Certificates)
  1. اضغط علامة الزائد `+` لإنشاء شهادة جديدة.
  2. اختر نوع الشهادة: Apple Distribution ثم اضغط Continue.
  3. ارفع ملف CertificateSigningRequest.certSigningRequest الذي تم توليده.
  4. اضغط Generate ثم اضغط Download لتحميل الشهادة (اسمها: distribution.cer).

ج) دمج الشهادة مع المفتاح الخاص وتوليد ملف .p12:

ضع ملف distribution.cer في نفس المجلد الذي يحتوي على المفتاح الخاص، ثم نفذ:

Terminal (Bash)
# 1. تحويل الشهادة من تنسيق DER إلى PEM openssl x509 -in distribution.cer -inform DER -out distribution.pem -outform PEM # 2. إنشاء ملف .p12 متوافق مع نظام ماك وسيرفرات CI/CD (هام: استخدم /usr/bin/openssl) /usr/bin/openssl pkcs12 -export \ -inkey distribution_private_key.key \ -in distribution.pem \ -out distribution.p12 \ -passout pass:YOUR_P12_PASSWORD
💡
سر عدم حدوث خطأ "Unknown format in import":
استخدام /usr/bin/openssl المدمج في نظام macOS هو الذي يضمن تشفير ملف الـ p12 بخوارزميات Legacy المتوافقة مع أداة security داخل سيرفرات GitHub، وتجنب خوارزميات OpenSSL 3 الحديثة التي تسبب فشل استيراد الشهادة على الـ CI.
3
إنشاء ملف الـ Provisioning Profile (.mobileprovision)
ربط التطبيق والشهادة وتجهيز بروفايل الـ App Store
يحدد الـ Provisioning Profile لشركة Apple أن تطبيقك مصرح له بالنشر على المتجر باستخدام شهادة التوزيع المعتمدة:
🔗 بوابة Apple Developer: قائمة الـ Provisioning Profiles
  1. اضغط على علامة `+` لإنشاء بروفايل جديد.
  2. تحت قسم Distribution، اختر App Store ثم اضغط Continue.
  3. App ID: اختر التطبيق الخاص بك (com.yourcompany.yourapp).
  4. Certificates: اختر شهادة Apple Distribution التي تم إنشاؤها في الخطوة السابقة.
  5. Profile Name: اكتب اسماً دقيقاً ومعبراً (مثال: YourApp_AppStore).
  6. اضغط Generate ثم Download لتحميل الملف (امتداده .mobileprovision).
4
تحويل الملفات إلى Base64 لإضافتها في GitHub Secrets
تشفير الملفات الثنائية كنصوص نصية نقية
لا يقبل GitHub تخزين ملفات binary مباشرة داخل الـ Secrets، لذلك نقوم بتحويل الملفات الثلاثة إلى نصوص Base64 بواسطة التيرمينال:
Terminal (macOS / Linux)
# 1. تحويل مفتاح الـ API (.p8) base64 -i AuthKey_XXXXXXXXXX.p8 -o api_key_base64.txt # 2. تحويل شهادة التوزيع (.p12) base64 -i distribution.p12 -o cert_base64.txt # 3. تحويل ملف الـ Provisioning Profile (.mobileprovision) base64 -i YourApp_AppStore.mobileprovision -o profile_base64.txt

ستظهر لك الآن 3 ملفات نصية (.txt)، سنقوم بنسخ محتوى كل ملف بالكامل واستخدامه في الخطوة التالية.

5
إضافة الـ Secrets في مستودع GitHub
قائمة المتغيرات السرية السبعة (Repository Secrets)
ادخل على مستودع مشروعك على GitHub ثم توجه إلى المسار التالي:
Settings ➔ Secrets and variables ➔ Actions ➔ اضغط New repository secret
اسم السر (Secret Name) الوصف ومصدر القيمة مثال توضيحي
APP_STORE_CONNECT_KEY_ID معرف المفتاح المكون من 10 خانات والمستخرج من الخطوة 1 U5943UX5VN
APP_STORE_CONNECT_ISSUER_ID معرف الـ Issuer (UUID) الموجود أعلى صفحة Keys في Apple 7b528716-19b5-407f-...
APP_STORE_CONNECT_PRIVATE_KEY_BASE64 محتوى ملف api_key_base64.txt كاملاً بدون أي مسافات زائدة نص Base64 يبدأ بـ LS0tLS...
BUILD_CERTIFICATE_BASE64 محتوى ملف cert_base64.txt (الشهادة المشفرة) نص Base64 كامل
P12_PASSWORD كلمة السر التي اخترتها لحماية ملف distribution.p12 كلمة المرور السرية الخاصة بك
BUILD_PROVISION_PROFILE_BASE64 محتوى ملف profile_base64.txt كاملاً نص Base64 كامل
KEYCHAIN_PASSWORD أي كلمة مرور عشوائية لفتح الكي تشين المؤقت في سيرفر البناء AutoCiKeychainPass2026!
6
إعدادات ملفات المشروع (ExportOptions & Info.plist)

ملف أساسي يخبر محرك xcodebuild بكيفية توقيع وتصدير حزمة الـ IPA تلقائياً دون الحاجة لواجهة Xcode الرسومية:

XML • ios/ExportOptions.plist
<?xml version="1.0" encoding="UTF-8"?> <!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd"> <plist version="1.0"> <dict> <key>method</key> <string>app-store</string> <key>teamID</key> <string>YOUR_TEAM_ID</string> <key>signingStyle</key> <string>manual</string> <key>provisioningProfiles</key> <dict> <key>com.yourcompany.yourapp</key> <string>YourApp_AppStore</string> </dict> <key>destination</key> <string>export</string> <key>uploadSymbols</key> <true/> <key>compileBitcode</key> <false/> <key>stripSwiftSymbols</key> <true/> </dict> </plist>

تأكد من أن ملف ios/Runner/Info.plist يقرأ رقم الإصدار والـ Build من متغيرات Flutter بدلاً من الأرقام الثابتة:

XML Snippet • ios/Runner/Info.plist
<key>CFBundleShortVersionString</key> <string>$(FLUTTER_BUILD_NAME)</string> <key>CFBundleVersion</key> <string>$(FLUTTER_BUILD_NUMBER)</string>

أضف هذه الأسطر في ملف ios/Flutter/Release.xcconfig لإجبار Xcode على التوقيع اليدوي ومنعه من محاولة البحث الأونلاين عن حسابات Apple أثناء تشغيل السيرفر السحابي:

xcconfig • ios/Flutter/Release.xcconfig
CODE_SIGN_STYLE = Manual CODE_SIGN_IDENTITY = Apple Distribution PROVISIONING_PROFILE_SPECIFIER = YourApp_AppStore DEVELOPMENT_TEAM = YOUR_TEAM_ID
7
ملف الـ Workflow الكامل (.github/workflows/deploy_ios.yml)
الملف الشامل المعتمد والجاهز للاستخدام الفوري
أنشئ ملفاً جديداً في مشروعك بالمسار: .github/workflows/deploy_ios.yml والصق الكود التالي. يتميز هذا الملف بـ:
  • الزيادة التلقائية التراكمية لرقم الإصدار (Auto-Increment Build Number) عبر رقم عملية الرفع GITHUB_RUN_NUMBER.
  • إمكانية تحديد Build Number يدوي اختياري عند تشغيل الـ Workflow يدوياً.
  • معالجة تلقائية لـ Base64 Padding عبر بايثون لتفادي خطأ binascii.Error: Incorrect padding.
  • إعداد المفتاح الخاص لـ App Store Connect في المسار الصحيح المعتمد من Apple.
YAML • .github/workflows/deploy_ios.yml
name: Deploy iOS to App Store on: push: branches: - release # يعمل تلقائياً عند الدفع أو الدمج في برانش release pull_request: branches: - release # تشغيل الفحص عند إنشاء Pull Request على برانش release workflow_dispatch: inputs: custom_build_number: description: 'رقم إصدار محدد يدوياً (اختياري - اتركه فارغاً للزيادة التلقائية)' required: false default: '' jobs: deploy: name: Build & Upload to App Store runs-on: macos-26 # يحتوي على أحدث بيئات Xcode و iOS SDK المعتمدين من Apple timeout-minutes: 60 steps: - name: Checkout Code uses: actions/checkout@v4 - name: Verify Xcode & iOS SDK run: | xcodebuild -version echo "iOS SDK: $(xcrun --show-sdk-version --sdk iphoneos)" - name: Set up Flutter uses: subosito/flutter-action@v2 with: channel: 'stable' cache: true - name: Calculate Version & Auto-Increment Build Number id: versioning run: | # 1. استخراج رقم النسخة والـ Build الحالي من pubspec.yaml RAW_VERSION=$(grep '^version:' pubspec.yaml | sed -E 's/version:[[:space:]]*//') VERSION_NAME=$(echo "$RAW_VERSION" | cut -d'+' -f1) BASE_BUILD=$(echo "$RAW_VERSION" | cut -d'+' -f2) if [ -z "$BASE_BUILD" ] || [ "$BASE_BUILD" = "$VERSION_NAME" ]; then BASE_BUILD=1 fi # 2. فحص إذا كان هناك Build Number مدخل يدوياً عبر workflow_dispatch CUSTOM_BUILD="${{ inputs.custom_build_number }}" if [ -n "$CUSTOM_BUILD" ]; then BUILD_NUMBER="$CUSTOM_BUILD" else # زيادة تلقائية تصاعدية تراكمية مع كل عملية تشغيل على جيت هب BUILD_NUMBER=$(( BASE_BUILD + GITHUB_RUN_NUMBER )) fi # 3. حقن رقم الإصدار والـ Build في pubspec.yaml و Xcode لضمان التوافق التام sed -i '' "s/^version:.*/version: $VERSION_NAME+$BUILD_NUMBER/g" pubspec.yaml if [ -f ios/Runner.xcodeproj/project.pbxproj ]; then sed -i '' "s/CURRENT_PROJECT_VERSION = [0-9]*;/CURRENT_PROJECT_VERSION = $BUILD_NUMBER;/g" ios/Runner.xcodeproj/project.pbxproj sed -i '' "s/MARKETING_VERSION = [^;]*;/MARKETING_VERSION = $VERSION_NAME;/g" ios/Runner.xcodeproj/project.pbxproj fi echo "VERSION_NAME=$VERSION_NAME" >> $GITHUB_ENV echo "BUILD_NUMBER=$BUILD_NUMBER" >> $GITHUB_ENV echo "=========================================" echo "🚀 Deploying Version: $VERSION_NAME (Build $BUILD_NUMBER)" echo "=========================================" - name: Install Apple Certificate env: BUILD_CERTIFICATE_BASE64: ${{ secrets.BUILD_CERTIFICATE_BASE64 }} P12_PASSWORD: ${{ secrets.P12_PASSWORD }} KEYCHAIN_PASSWORD: ${{ secrets.KEYCHAIN_PASSWORD }} CERT_PATH: ${{ runner.temp }}/certificate.p12 KEYCHAIN_PATH: ${{ runner.temp }}/app-signing.keychain-db run: | # فك تشفير الشهادة باستخدام بايثون مع معالجة الـ padding تلقائياً python3 -c "import base64, os; s = os.environ['BUILD_CERTIFICATE_BASE64'].strip(); s += '=' * (-len(s) % 4); open(os.environ['CERT_PATH'], 'wb').write(base64.b64decode(s))" /usr/bin/openssl pkcs12 -in "$CERT_PATH" -noout -info -passin "pass:$P12_PASSWORD" # إنشاء Keychain مؤقت وإضافته لقائمة البحث /usr/bin/security create-keychain -p "$KEYCHAIN_PASSWORD" "$KEYCHAIN_PATH" /usr/bin/security set-keychain-settings -lut 21600 "$KEYCHAIN_PATH" /usr/bin/security unlock-keychain -p "$KEYCHAIN_PASSWORD" "$KEYCHAIN_PATH" /usr/bin/security list-keychains -d user -s "$KEYCHAIN_PATH" $(/usr/bin/security list-keychains -d user | tr -d '"') # استيراد الشهادة إلى Keychain وتفويض codesign /usr/bin/security import "$CERT_PATH" -k "$KEYCHAIN_PATH" -P "$P12_PASSWORD" -T /usr/bin/codesign -T /usr/bin/security /usr/bin/security set-key-partition-list -S apple-tool:,apple:,codesign: -s -k "$KEYCHAIN_PASSWORD" "$KEYCHAIN_PATH" - name: Install Provisioning Profile env: BUILD_PROVISION_PROFILE_BASE64: ${{ secrets.BUILD_PROVISION_PROFILE_BASE64 }} PP_PATH: ${{ runner.temp }}/app_distribution.mobileprovision run: | mkdir -p ~/Library/MobileDevice/Provisioning\ Profiles python3 -c "import base64, os; s = os.environ['BUILD_PROVISION_PROFILE_BASE64'].strip(); s += '=' * (-len(s) % 4); open(os.environ['PP_PATH'], 'wb').write(base64.b64decode(s))" # استخراج الـ UUID واسم البروفايل تلقائياً بدون كتابة أي بيانات خاصة لأي تطبيق PROFILE_UUID=$(/usr/libexec/PlistBuddy -c "Print UUID" /dev/stdin <<< $(security cms -D -i "$PP_PATH") 2>/dev/null || echo "") PROFILE_NAME=$(/usr/libexec/PlistBuddy -c "Print Name" /dev/stdin <<< $(security cms -D -i "$PP_PATH") 2>/dev/null || echo "") echo "Extracted Profile Name: $PROFILE_NAME" echo "Extracted Profile UUID: $PROFILE_UUID" if [ -n "$PROFILE_UUID" ]; then cp "$PP_PATH" ~/Library/MobileDevice/Provisioning\ Profiles/${PROFILE_UUID}.mobileprovision fi if [ -n "$PROFILE_NAME" ]; then cp "$PP_PATH" "$HOME/Library/MobileDevice/Provisioning Profiles/${PROFILE_NAME}.mobileprovision" fi cp "$PP_PATH" ~/Library/MobileDevice/Provisioning\ Profiles/AppStore.mobileprovision - name: Setup Environment Files (Optional) env: APP_ENV_BASE64: ${{ secrets.APP_ENV_BASE64 }} run: | # في حال كان التطبيق يعتمد على ملفات .env مشفرة كـ Secret mkdir -p env if [ -n "$APP_ENV_BASE64" ]; then echo "$APP_ENV_BASE64" | base64 --decode > env/.env elif [ ! -f env/.env ]; then touch env/.env fi - name: Install Dependencies run: | flutter config --no-enable-swift-package-manager mkdir -p build/ios/SourcePackages flutter pub get - name: Prepare CocoaPods run: | if [ -f ios/install_pods.sh ]; then bash ios/install_pods.sh else cd ios && pod install --repo-update fi - name: Build iOS IPA run: | flutter build ipa --release \ --build-name="$VERSION_NAME" \ --build-number="$BUILD_NUMBER" \ --export-options-plist=ios/ExportOptions.plist - name: Upload to App Store Connect / TestFlight env: APP_STORE_CONNECT_KEY_ID: ${{ secrets.APP_STORE_CONNECT_KEY_ID }} APP_STORE_CONNECT_ISSUER_ID: ${{ secrets.APP_STORE_CONNECT_ISSUER_ID }} APP_STORE_CONNECT_PRIVATE_KEY_BASE64: ${{ secrets.APP_STORE_CONNECT_PRIVATE_KEY_BASE64 }} run: | mkdir -p ~/.appstoreconnect/private_keys mkdir -p ~/.private_keys python3 -c "import base64, os; s = os.environ['APP_STORE_CONNECT_PRIVATE_KEY_BASE64'].strip(); s += '=' * (-len(s) % 4); open(os.path.expanduser('~/.appstoreconnect/private_keys/AuthKey_' + os.environ['APP_STORE_CONNECT_KEY_ID'] + '.p8'), 'wb').write(base64.b64decode(s))" cp ~/.appstoreconnect/private_keys/AuthKey_${APP_STORE_CONNECT_KEY_ID}.p8 ~/.private_keys/AuthKey_${APP_STORE_CONNECT_KEY_ID}.p8 IPA_PATH=$(find build/ios/ipa -name "*.ipa" | head -n 1) if [ -z "$IPA_PATH" ]; then echo "❌ Error: IPA file not found in build/ios/ipa" exit 1 fi echo "🚀 Uploading $IPA_PATH to App Store Connect..." xcrun altool --upload-app \ --type ios \ --file "$IPA_PATH" \ --apiKey "$APP_STORE_CONNECT_KEY_ID" \ --apiIssuer "$APP_STORE_CONNECT_ISSUER_ID" echo "✅ Upload completed successfully to App Store Connect!"

سجل حل المشكلات والأخطاء الشائعة (Troubleshooting Hub)
🔍
❌ SecKeychainItemImport: Unknown format in import
السبب: تم إنشاء ملف الشهادة .p12 باستخدام OpenSSL 3 الحديث بنظام تشفير AES-256 الذي لا تتعرف عليه أداة security الكلاسيكية في macOS.
✅
الحل: أنشئ الـ p12 باستخدام مسار /usr/bin/openssl المدمج في نظام ماك، وتأكد أن الملف المؤقت المستخرج في السيرفر يحمل امتداد .p12.
❌ binascii.Error: Incorrect padding
السبب: نصوص الـ Base64 قد تفقد إشارات التكميل (=) عند حفظها في GitHub Secrets أو تمريرها كمتغيرات بيئية.
✅
الحل: استخدام سطر فك التشفير الذكي في بايثون المعتمد في الـ Workflow:
s += '=' * (-len(s) % 4) والذي يقوم بإصلاح الـ padding تلقائياً قبل فك التشفير.
❌ KeyError: 'CERT_PATH' أو متغيرات فارغة في بايثون

❌ No profiles found matching / No signing certificate

✅

✅

flutter config --no-enable-swift-package-manager وإنشاء مجلد build/ios/SourcePackages.
